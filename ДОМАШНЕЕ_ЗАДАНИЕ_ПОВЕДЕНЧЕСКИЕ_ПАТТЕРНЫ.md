### ✅ ПАТТЕРН 1: STRATEGY (Стратегия)

**Описание:**  
Определяет семейство алгоритмов, инкапсулирует каждый из них и делает их взаимозаменяемыми. Strategy позволяет изменять алгоритмы независимо от клиентов, которые ими пользуются.

**Где реализовано:**  
`Granny's Recipe Keeper/Models/Recipe/BehavioralPatternsExamples.swift`

**Применение в проекте:**  
Различные стратегии сортировки рецептов:
- `SortByNameStrategy` - сортировка по имени (A-Z)
- `SortByNameDescendingStrategy` - сортировка по имени (Z-A)
- `SortByDateNewestStrategy` - по дате (новые первые)
- `SortByDateOldestStrategy` - по дате (старые первые)
- `SortByCookingTimeStrategy` - по времени приготовления
- `SortByCaloriesStrategy` - по калориям
- `SortByDifficultyStrategy` - по сложности
- `SortByFavoritesStrategy` - избранные первыми

**Ключевые компоненты:**
```swift
// Протокол стратегии
protocol RecipeSortStrategy {
    var name: String { get }
    func sort(recipes: [Recipe]) -> [Recipe]
}

// Конкретная стратегия
class SortByNameStrategy: RecipeSortStrategy {
    var name: String { "Name (A-Z)" }
    func sort(recipes: [Recipe]) -> [Recipe] {
        return recipes.sorted { $0.name < $1.name }
    }
}

// Контекст
class RecipeSorter {
    private var strategy: RecipeSortStrategy
    
    func setStrategy(_ strategy: RecipeSortStrategy) {
        self.strategy = strategy
    }
    
    func sort(recipes: [Recipe]) -> [Recipe] {
        return strategy.sort(recipes: recipes)
    }
}
```

**Преимущества:**
- ✅ Легко добавлять новые стратегии сортировки без изменения существующего кода
- ✅ Клиентский код не зависит от конкретной реализации алгоритма
- ✅ Упрощает тестирование каждой стратегии отдельно
- ✅ Можно изменять стратегию в runtime

**Пример использования:**
```swift
let recipes = RecipesRepository.shared.getAllRecipes()
let sorter = RecipeSorter(strategy: SortByNameStrategy())
let sortedRecipes = sorter.sort(recipes: recipes)

// Изменить стратегию в runtime
sorter.setStrategy(SortByDateNewestStrategy())
let sortedByDate = sorter.sort(recipes: recipes)
```

### ✅ ПАТТЕРН 2: MEMENTO (Хранитель)

**Описание:**  
Захватывает и внешне хранит внутреннее состояние объекта так, чтобы позднее можно было восстановить объект в этом состоянии, не нарушая инкапсуляции.

**Где реализовано:**  
`Granny's Recipe Keeper/Models/Recipe/BehavioralPatternsExamples.swift`

**Применение в проекте:**  
Сохранение и восстановление состояния фильтров рецептов (выбранные теги, сложность, сортировка).

**Ключевые компоненты:**
```swift
// Memento - снимок состояния
struct RecipeFilterMemento {
    let selectedTags: Set<String>
    let selectedDifficulty: String?
    let sortStrategyIndex: Int
    let timestamp: Date
}

// Originator - объект, состояние которого сохраняется
class RecipeFilterState {
    private(set) var selectedTags: Set<String> = []
    private(set) var selectedDifficulty: String?
    private(set) var sortStrategyIndex: Int = 0
    
    func createMemento() -> RecipeFilterMemento { ... }
    func restore(from memento: RecipeFilterMemento) { ... }
}

// Caretaker - управляет сохранением
class RecipeFilterCaretaker {
    static let shared = RecipeFilterCaretaker()
    private var history: [RecipeFilterMemento] = []
    
    func saveMemento(_ memento: RecipeFilterMemento) { ... }
    func getLastMemento() -> RecipeFilterMemento? { ... }
}
```

**Преимущества:**
- ✅ Сохраняет настройки пользователя между сессиями
- ✅ Не нарушает инкапсуляцию объекта
- ✅ Позволяет восстановить предыдущее состояние
- ✅ Упрощает реализацию Undo/Redo функциональности

**Пример использования:**
```swift
let filterState = RecipeFilterState()
let caretaker = RecipeFilterCaretaker.shared

// Применить фильтры
filterState.applyFilters(tags: ["Vegetarian"], difficulty: "easy", sortIndex: 2)

// Сохранить состояние
let memento = filterState.createMemento()
caretaker.saveMemento(memento)

// Восстановить состояние
if let savedMemento = caretaker.getLastMemento() {
    filterState.restore(from: savedMemento)
}
```

### ✅ ПАТТЕРН 3: OBSERVER (Наблюдатель)

**Описание:**  
Определяет зависимость типа "один-ко-многим" между объектами таким образом, что при изменении состояния одного объекта все зависящие от него объекты уведомляются об этом и автоматически обновляются.

**Где реализовано:**  
В проекте реализован через **Delegate паттерн** во множестве мест:
- `RecipeEditViewController.swift` - `RecipeEditViewControllerDelegate`
- `FilterViewController.swift` - `FilterViewControllerDelegate`
- `RecipesViewController.swift` - реализация делегатов

**Применение в проекте:**  
Уведомление контроллеров об изменениях в данных (сохранение рецепта, применение фильтров и т.д.)

**Ключевые компоненты:**
```swift
// Subject - протокол наблюдателя
protocol RecipeEditViewControllerDelegate: AnyObject {
    func didSaveRecipe()
}

// Concrete Subject - издатель
class RecipeEditViewController: UIViewController {
    weak var delegate: RecipeEditViewControllerDelegate?
    
    func saveRecipe() {
        // Сохранение рецепта...
        delegate?.didSaveRecipe() // Уведомление наблюдателей
    }
}

// Observer - подписчик
extension RecipesViewController: RecipeEditViewControllerDelegate {
    func didSaveRecipe() {
        loadRecipes() // Реакция на уведомление
    }
}
```

**Преимущества:**
- ✅ Слабая связанность между объектами
- ✅ Множество наблюдателей могут реагировать на изменения
- ✅ Динамическое добавление/удаление наблюдателей
- ✅ Поддержка broadcast коммуникации

### ✅ ПАТТЕРН 4: TEMPLATE METHOD (Шаблонный метод)

**Описание:**  
Определяет скелет алгоритма в операции, оставляя некоторые шаги подклассам. Template Method позволяет подклассам переопределить определенные шаги алгоритма, не изменяя его структуру.

**Где реализовано:**  
`Granny's Recipe Keeper/Models/Recipe/BehavioralPatternsExamples.swift`

**Применение в проекте:**  
Базовый процесс загрузки и обработки данных из различных API (TheMealDB, Unsplash и т.д.)

**Ключевые компоненты:**
```swift
// Абстрактный класс с шаблонным методом
class APIDataProcessor {
    // Шаблонный метод - определяет общий алгоритм
    final func processData(completion: @escaping (Result<[Recipe], Error>) -> Void) {
        guard validateBeforeLoad() else { return }
        
        fetchDataFromAPI { result in
            let processedData = self.processRawData(result)
            let recipes = self.convertToRecipes(processedData)
            self.finalizeProcessing(recipes)
            completion(.success(recipes))
        }
    }
    
    // Шаги, которые могут быть переопределены
    func validateBeforeLoad() -> Bool { true }
    func fetchDataFromAPI(completion: @escaping (Result<Any, Error>) -> Void) { }
    func processRawData(_ rawData: Any) -> Any { rawData }
    func convertToRecipes(_ data: Any) -> [Recipe] { [] }
    func finalizeProcessing(_ recipes: [Recipe]) { }
}

// Конкретная реализация
class TheMealDBDataProcessor: APIDataProcessor {
    override func fetchDataFromAPI(completion: @escaping (Result<Any, Error>) -> Void) {
        TheMealDBService.shared.getRecipesByCategory("Dessert") { result in
            completion(result)
        }
    }
    
    override func convertToRecipes(_ data: Any) -> [Recipe] {
        guard let mealDBRecipes = data as? [TheMealDBRecipe] else { return [] }
        return mealDBRecipes.compactMap { $0.toRecipe() }
    }
}
```

**Преимущества:**
- ✅ Избегает дублирования кода
- ✅ Определяет общую структуру алгоритма
- ✅ Подклассы могут изменять только необходимые шаги
- ✅ Инверсия контроля ("Hollywood Principle")

### ✅ ПАТТЕРН 5: COMMAND (Команда)

**Описание:**  
Инкапсулирует запрос как объект, позволяя параметризовать клиентов с различными запросами, ставить запросы в очередь или логировать их, а также поддерживать отмену операций.

**Где реализовано:**  
1. `ImageLoadOperation.swift` - команды загрузки изображений
2. `BehavioralPatternsExamples.swift` - команды для операций с рецептами

**Применение в проекте:**  
- Загрузка изображений через очередь операций
- Операции с рецептами (добавление в избранное, архивирование) с поддержкой Undo

**Ключевые компоненты:**
```swift
// Command - интерфейс команды
protocol RecipeCommand {
    func execute()
    func undo()
}

// Concrete Command
class AddToFavoritesCommand: RecipeCommand {
    private let recipe: Recipe
    
    func execute() {
        RecipesRepository.shared.addToFavorites(recipe)
    }
    
    func undo() {
        RecipesRepository.shared.removeFromFavorites(recipe)
    }
}

// Invoker - выполняет команды
class RecipeCommandInvoker {
    private var commandHistory: [RecipeCommand] = []
    
    func executeCommand(_ command: RecipeCommand) {
        command.execute()
        commandHistory.append(command)
    }
    
    func undoLastCommand() {
        commandHistory.popLast()?.undo()
    }
}

// ImageLoadOperation как команда
class ImageLoadOperation: Operation {
    override func main() {
        // Выполнение команды загрузки
    }
    
    override func cancel() {
        // Отмена команды
    }
}
```

**Преимущества:**
- ✅ Инкапсуляция запросов как объектов
- ✅ Поддержка Undo/Redo операций
- ✅ Возможность постановки команд в очередь
- ✅ Изоляция кода выполнения от кода инициации
