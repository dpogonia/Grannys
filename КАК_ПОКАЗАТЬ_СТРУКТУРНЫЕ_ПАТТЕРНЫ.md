## Как продемонстрировать

### Вариант 1: Через Xcode (рекомендуется)

1. **Откройте проект в Xcode**

2. **Используйте поиск (⌘+Shift+F):**
   - `ПАТТЕРН 1: FACADE` → покажет фасад
   - `ПАТТЕРН 2: ADAPTER` → покажет адаптеры

3. **Покажите Facade (RecipesRepository):**
   ```swift
   // Простой API фасада
   let recipes = RecipesRepository.shared.getAllRecipes()
   repository.saveRecipe(recipe)
   
   // Без фасада нужно было бы:
   // - Создать NSManagedObjectContext
   // - Создать NSFetchRequest
   // - Настроить NSPredicate
   // - Обработать ошибки
   // - Преобразовать Entity → Model
   // Минимум 15-20 строк кода!
   ```

4. **Покажите Adapter:**
   ```swift
   // TheMealDB API → Recipe
   let adapter = TheMealDBRecipeAdapter(mealDBRecipe: mealDB)
   let recipe = adapter.adapt()
   
   // Или через extension (проще)
   let recipe = mealDBRecipe.toRecipe()
   
   // Generic API → Recipe
   let recipe = apiRecipe.toRecipe()
   
   // Единый интерфейс для разных API!
   ```

5. **Запустите примеры (опционально):**
   ```swift
   let examples = StructuralPatternsExamples()
   examples.runAllExamples()
   ```

## Ключевые моменты для объяснения

### FACADE (Фасад)
**Где используется:** RecipesRepository

**Что делает:**
- Скрывает сложность Core Data
- Предоставляет простой API
- Упрощает код с 20+ строк до 1 строки

**Что скрывает фасад:**
- NSManagedObjectContext и его настройка
- NSFetchRequest и сложные предикаты
- Маппинг Entity ↔ Model
- Управление связями между сущностями
- Обработка ошибок Core Data
- Инициализация дефолтных данных

**Пример преимущества:**

❌ **Без фасада:**
```swift
let context = CoreDataManager.shared.viewContext
let fetchRequest = NSFetchRequest<RecipeEntity>(entityName: "RecipeEntity")
fetchRequest.predicate = NSPredicate(format: "isArchived == %@", false)
fetchRequest.sortDescriptors = [NSSortDescriptor(key: "createdAt", ascending: false)]
do {
    let entities = try context.fetch(fetchRequest)
    let recipes = entities.compactMap { Recipe(from: $0) }
} catch {
    print("Error: \(error)")
}
// ~15 строк кода
```

✅ **С фасадом:**
```swift
let recipes = RecipesRepository.shared.getAllRecipes()
// 1 строка кода!
```

### ADAPTER (Адаптер)
**Где используется:** 
- TheMealDBRecipeAdapter
- GenericRecipeAdapter

**Что делает:**
- Преобразует данные из разных API в единый формат Recipe
- TheMealDB: 20 полей ингредиентов → массив Ingredient
- Generic API: APIIngredient → Ingredient

**Проблема, которую решает:**
Приложение работает с разными API:
- TheMealDB: `strIngredient1...strIngredient20`, `strMeasure1...strMeasure20`
- Generic API: `extendedIngredients: [APIIngredient]`
- Нужен единый формат: `ingredients: [Ingredient]`

**Решение:**
Адаптеры преобразуют разные форматы → Recipe

**Пример преимущества:**

❌ **Без адаптера:**
```swift
// Логика преобразования разбросана по коду
// В одном месте:
let recipe1 = Recipe(name: mealDB.strMeal ?? "", ...)
// В другом месте:
let recipe2 = Recipe(name: api.title, ...)
// Дублирование кода!
```

✅ **С адаптером:**
```swift
// Единый интерфейс для всех API
let recipe1 = mealDB.toRecipe()
let recipe2 = api.toRecipe()
// Логика в одном месте (адаптере)
```

## Частые вопросы

**Q: Почему именно эти паттерны?**
A: 
- **Facade:** RecipesRepository уже был в проекте как фасад для Core Data
- **Adapter:** Проект работает с разными API, нужна унификация данных
- Оба паттерна решают реальные проблемы, а не "для галочки"

**Q: Можно было выбрать другие паттерны?**
A: Да, но эти паттерны:
- Уже использовались в коде (Facade)
- Решают реальную проблему (Adapter для разных API)
- Соответствуют best practices из лекции

**Q: Где находятся комментарии к паттернам?**
A: 
- Поиск в Xcode: `"ДОМАШНЕЕ ЗАДАНИЕ: СТРУКТУРНЫЕ ПАТТЕРНЫ"`
- Все файлы с реализацией содержат подробные комментарии
- Каждый паттерн объяснен: что это, зачем, как работает

## Структура паттернов (для объяснения)

### FACADE:
```
Клиент
   │
   ├─► RecipesRepository.shared.getAllRecipes()    [Простой API]
   │                        │
   │                        └─► Core Data:
   │                            - NSManagedObjectContext
   │                            - NSFetchRequest
   │                            - NSPredicate
   │                            - Entity mapping
   │                            [Сложная система]
```

### ADAPTER:
```
TheMealDB API              Generic API
(20 полей ingr.)          (extendedIngredients)
      │                           │
      ├─► TheMealDBAdapter        ├─► GenericAdapter
      │                           │
      └───────────┬───────────────┘
                  │
                  ▼
              Recipe
          (единый формат)
```
