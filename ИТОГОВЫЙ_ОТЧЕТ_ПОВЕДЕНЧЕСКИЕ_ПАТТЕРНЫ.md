## Детальное описание реализованных паттернов

### 1. STRATEGY (Стратегия) - 40 баллов

#### Описание
Паттерн Strategy позволяет определить семейство алгоритмов, инкапсулировать каждый из них и сделать их взаимозаменяемыми.

#### Где реализовано
- **Файл:** `BehavioralPatternsExamples.swift`
- **Строки:** 14-169

#### Что сделано
Реализовано **8 различных стратегий** сортировки рецептов:

| № | Стратегия | Описание |
|---|-----------|----------|
| 1 | `SortByNameStrategy` | Сортировка по имени (A-Z) |
| 2 | `SortByNameDescendingStrategy` | Сортировка по имени (Z-A) |
| 3 | `SortByDateNewestStrategy` | По дате (новые первые) |
| 4 | `SortByDateOldestStrategy` | По дате (старые первые) |
| 5 | `SortByCookingTimeStrategy` | По времени приготовления |
| 6 | `SortByCaloriesStrategy` | По калориям |
| 7 | `SortByDifficultyStrategy` | По сложности |
| 8 | `SortByFavoritesStrategy` | Избранные первыми |

#### Ключевые компоненты
```swift
// Протокол стратегии
protocol RecipeSortStrategy {
    var name: String { get }
    func sort(recipes: [Recipe]) -> [Recipe]
}

// Контекст
class RecipeSorter {
    private var strategy: RecipeSortStrategy
    func setStrategy(_ strategy: RecipeSortStrategy)
    func sort(recipes: [Recipe]) -> [Recipe]
}

// Менеджер стратегий
class RecipeSortStrategyManager {
    static let shared: RecipeSortStrategyManager
    func getAllStrategies() -> [RecipeSortStrategy]
}
```

#### Преимущества реализации
✅ Легко добавлять новые стратегии без изменения кода  
✅ Каждая стратегия изолирована и легко тестируется  
✅ Можно менять стратегию в runtime  
✅ Код соответствует принципу Open/Closed  

#### Примеры использования
- `strategyExample1_SortByName()` - простая сортировка
- `strategyExample2_ChangingStrategy()` - смена стратегии в runtime
- `strategyExample3_AllStrategies()` - демонстрация всех стратегий

### 2. MEMENTO (Хранитель) - 40 баллов

#### Описание
Паттерн Memento захватывает и внешне хранит внутреннее состояние объекта для последующего восстановления без нарушения инкапсуляции.

#### Где реализовано
- **Файл:** `BehavioralPatternsExamples.swift`
- **Строки:** 238-327

#### Что сделано
Реализована система сохранения и восстановления состояния фильтров рецептов:

| Компонент | Класс/Структура | Роль |
|-----------|-----------------|------|
| Memento | `RecipeFilterMemento` | Снимок состояния |
| Originator | `RecipeFilterState` | Объект, состояние которого сохраняется |
| Caretaker | `RecipeFilterCaretaker` | Управляет сохранением/восстановлением |

#### Ключевые компоненты
```swift
// Memento - снимок состояния
struct RecipeFilterMemento {
    let selectedTags: Set<String>
    let selectedDifficulty: String?
    let sortStrategyIndex: Int
    let timestamp: Date
}

// Originator - объект с состоянием
class RecipeFilterState {
    func createMemento() -> RecipeFilterMemento
    func restore(from memento: RecipeFilterMemento)
}

// Caretaker - хранитель
class RecipeFilterCaretaker {
    static let shared: RecipeFilterCaretaker
    func saveMemento(_ memento: RecipeFilterMemento)
    func getLastMemento() -> RecipeFilterMemento?
}
```

#### Преимущества реализации
✅ Сохранение настроек пользователя между сессиями  
✅ Не нарушает инкапсуляцию объекта  
✅ Поддержка истории состояний (до 10 записей)  
✅ Интеграция с UserDefaults для постоянного хранения  

#### Примеры использования
- `mementoExample1_SaveAndRestore()` - сохранение и восстановление
- `mementoExample2_MultipleStates()` - работа с историей состояний

### 3. OBSERVER (Наблюдатель) - БОНУС

#### Описание
Паттерн Observer определяет зависимость "один-ко-многим" между объектами, где изменение одного объекта приводит к уведомлению всех зависимых.

#### Где реализовано
Реализован через **Delegate паттерн** в нескольких местах:

| Делегат | Файл | Назначение |
|---------|------|------------|
| `RecipeEditViewControllerDelegate` | RecipeEditViewController.swift | Уведомление о сохранении рецепта |
| `FilterViewControllerDelegate` | FilterViewController.swift | Уведомление о применении фильтров |
| `CategoriesViewControllerDelegate` | CategoriesViewController.swift | Уведомление о выборе категории |
| `RecipeDetailViewControllerDelegate` | RecipeDetailViewController.swift | Уведомление об обновлении/удалении |
| `UnsplashImageSearchViewControllerDelegate` | UnsplashImageSearchViewController.swift | Уведомление о выборе изображения |

#### Добавлены комментарии
```swift
// В RecipeEditViewController.swift:
// ПАТТЕРН OBSERVER: Уведомление наблюдателей о сохранении рецепта
delegate?.didSaveRecipe()

// В RecipesViewController.swift:
// ПАТТЕРН OBSERVER: Реакция на уведомление
func didSaveRecipe() {
    loadRecipes()
}
```

#### Преимущества реализации
✅ Слабая связанность между объектами  
✅ Множество наблюдателей могут реагировать на изменения  
✅ Динамическое добавление/удаление наблюдателей  
✅ Используется во всем приложении для координации UI

### 4. TEMPLATE METHOD (Шаблонный метод) - БОНУС

#### Описание
Паттерн Template Method определяет скелет алгоритма, оставляя некоторые шаги подклассам.

#### Где реализовано
- **Файл:** `BehavioralPatternsExamples.swift`
- **Строки:** 435-584

#### Что сделано
Создан базовый класс `APIDataProcessor` с шаблонным методом для обработки данных из API:

**Шаги алгоритма:**
1. `validateBeforeLoad()` - валидация перед загрузкой
2. `fetchDataFromAPI()` - загрузка данных (должен быть переопределен)
3. `processRawData()` - обработка сырых данных
4. `validateProcessedData()` - валидация результата
5. `convertToRecipes()` - конвертация в модель (должен быть переопределен)
6. `finalizeProcessing()` - финализация
7. `handleError()` - обработка ошибок

**Конкретная реализация:** `TheMealDBDataProcessor`

#### Ключевые компоненты
```swift
// Абстрактный класс
class APIDataProcessor {
    // Шаблонный метод (final - нельзя переопределить)
    final func processData(completion: @escaping (Result<[Recipe], Error>) -> Void)
    
    // Шаги, которые могут быть переопределены
    func validateBeforeLoad() -> Bool
    func fetchDataFromAPI(completion: @escaping (Result<Any, Error>) -> Void)
    func processRawData(_ rawData: Any) -> Any
    // ...
}

// Конкретная реализация
class TheMealDBDataProcessor: APIDataProcessor {
    override func fetchDataFromAPI(...)
    override func convertToRecipes(_:) -> [Recipe]
}
```

#### Преимущества реализации
✅ Избегает дублирования кода  
✅ Определяет общую структуру алгоритма  
✅ Легко добавлять новые источники данных  
✅ Инверсия контроля ("Hollywood Principle")

### 5. COMMAND (Команда) - БОНУС

#### Описание
Паттерн Command инкапсулирует запрос как объект, позволяя параметризовать клиентов с различными запросами и поддерживать отмену.

#### Где реализовано

**1. Загрузка изображений:**
- **Файл:** `ImageLoadOperation.swift`
- **Строки:** 11-133

**2. Операции с рецептами:**
- **Файл:** `BehavioralPatternsExamples.swift`
- **Строки:** 650-782

#### Что сделано

**Команды для изображений:**
- `ImageLoadOperation` - команда загрузки изображения
- Поддержка отмены через `cancel()`
- Постановка в очередь через `OperationQueue`

**Команды для рецептов:**
- `AddToFavoritesCommand` - добавить в избранное
- `RemoveFromFavoritesCommand` - удалить из избранного
- `ArchiveRecipeCommand` - архивировать рецепт
- `RecipeCommandInvoker` - invoker с историей для Undo

#### Ключевые компоненты
```swift
// Протокол команды
protocol RecipeCommand {
    func execute()
    func undo()
}

// Конкретная команда
class AddToFavoritesCommand: RecipeCommand {
    func execute() { /* добавить в избранное */ }
    func undo() { /* удалить из избранного */ }
}

// Invoker
class RecipeCommandInvoker {
    func executeCommand(_ command: RecipeCommand)
    func undoLastCommand()
}

// ImageLoadOperation как команда
class ImageLoadOperation: Operation {
    override func main() { /* выполнение */ }
    override func cancel() { /* отмена */ }
}
```

#### Преимущества реализации
✅ Инкапсуляция запросов как объектов  
✅ Поддержка Undo/Redo операций  
✅ Команды можно ставить в очередь  
✅ Изоляция кода выполнения от инициации
