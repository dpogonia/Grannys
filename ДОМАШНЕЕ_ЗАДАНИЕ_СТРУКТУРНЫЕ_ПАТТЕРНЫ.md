## Реализованные паттерны

### 1. FACADE (ФАСАД) - 40 баллов

**Описание паттерна:**
Фасад предоставляет простой интерфейс к сложной системе классов, библиотеке или фреймворку. Он скрывает сложность системы и предоставляет удобный API для работы с ней.

**Применение в проекте:**
`RecipesRepository` является фасадом для сложной системы **Core Data**, упрощая работу с базой данных рецептов.

#### Реализация: RecipesRepository как Фасад

**Файл:** `Granny's Recipe Keeper/Models/Recipe/RecipesRepository.swift`
- **Строки:** 12-48 (описание паттерна и комментарии)
- **Назначение:** Упрощение работы с Core Data для всего приложения

**Что скрывает фасад:**

1. **NSManagedObjectContext** - сложная настройка контекста Core Data
2. **NSFetchRequest** - создание запросов для получения данных
3. **NSPredicate** - сложные предикаты для фильтрации
4. **Entity ↔ Model маппинг** - преобразование между RecipeEntity и Recipe
5. **Связи между сущностями** - управление many-to-many отношениями
6. **Инициализация данных** - создание дефолтных категорий
7. **Обработка ошибок** - централизованная обработка ошибок Core Data

**Простой API фасада:**

```swift
class RecipesRepository {
    // Получение данных
    func getAllRecipes(archived: Bool = false) -> [Recipe]
    func getRecipes(in category: Category?, archived: Bool = false) -> [Recipe]
    func searchRecipes(query: String, in category: Category? = nil) -> [Recipe]
    func getFavoriteRecipes() -> [Recipe]
    
    // Сохранение и удаление
    func saveRecipe(_ recipe: Recipe)
    func deleteRecipe(_ recipe: Recipe)
    
    // Работа с категориями
    func getAllCategories() -> [Category]
    func saveCategory(_ category: Category)
    func deleteCategory(_ category: Category)
    
    // Специальные операции
    func archiveRecipe(_ recipe: Recipe)
    func toggleFavorite(_ recipe: Recipe)
}
```

**Пример использования:**

✅ **С ФАСАДОМ** (просто):
```swift

```

### 2. ADAPTER (АДАПТЕР) - 40 баллов

**Описание паттерна:**
Адаптер позволяет объектам с несовместимыми интерфейсами работать вместе. Адаптер оборачивает объект и предоставляет ему новый интерфейс, совместимый с ожидаемым.

**Применение в проекте:**
Приложение получает данные о рецептах из **разных API** с разными структурами данных. Адаптеры преобразуют их в единый формат `Recipe`.

#### Реализация 1: TheMealDBRecipeAdapter

**Файл:** `Granny's Recipe Keeper/Models/Recipe/RecipeAdapters.swift`
- **Строки:** 1-50 (описание), 58-150 (реализация)
- **Назначение:** Преобразование данных из TheMealDB API в Recipe

**Проблема:**
TheMealDB API возвращает данные в специфичном формате:
- Название: `strMeal`
- Инструкции: `strInstructions`
- Ингредиенты: 20 отдельных полей (`strIngredient1`...`strIngredient20`)
- Количество: 20 отдельных полей (`strMeasure1`...`strMeasure20`)
- Теги: строка с разделителями `"Dessert,Sweet,Baking"`

**Решение:**
Адаптер преобразует эти данные в единый формат `Recipe`:

```swift
class TheMealDBRecipeAdapter: RecipeAdapter {
    private let mealDBRecipe: TheMealDBRecipe
    
    init(mealDBRecipe: TheMealDBRecipe) {
        self.mealDBRecipe = mealDBRecipe
    }
    
    func adapt() -> Recipe {
        // Преобразование 20 полей ингредиентов в массив
        let ingredients = extractIngredients()
        
        // Преобразование строки тегов в массив
        let tags = extractTags()
        
        // Создание Recipe с использованием Builder
        return RecipeBuilder(name: mealDBRecipe.strMeal ?? "Unknown")
            .with(instructions: mealDBRecipe.strInstructions ?? "")
            .with(imageURL: mealDBRecipe.strMealThumb ?? "")
            .addIngredients(ingredients)
            .addTags(tags)
            .build()
    }
}
```

**Пример использования:**
```swift
// Получили данные из TheMealDB API
let mealDBRecipe: TheMealDBRecipe = /* данные из API */

// Используем адаптер для преобразования
let adapter = TheMealDBRecipeAdapter(mealDBRecipe: mealDBRecipe)
let recipe = adapter.adapt()

// Или через extension (еще проще)
let recipe = mealDBRecipe.toRecipe()
```

#### Реализация 2: GenericRecipeAdapter

**Файл:** `Granny's Recipe Keeper/Models/Recipe/RecipeAdapters.swift`
- **Строки:** 152-250
- **Назначение:** Преобразование данных из Generic Recipe API в Recipe

**Проблема:**
Generic Recipe API возвращает данные в другом формате:
- Название: `title`
- Инструкции: `instructions` или `summary`
- Ингредиенты: массив `APIIngredient` с полями `amount: Double`, `unit: String`
- Теги: массив `[String]`

**Решение:**
```swift
class GenericRecipeAdapter: RecipeAdapter {
    private let apiRecipe: APIRecipe
    
    init(apiRecipe: APIRecipe) {
        self.apiRecipe = apiRecipe
    }
    
    func adapt() -> Recipe {
        // Преобразование APIIngredient в Ingredient
        let ingredients = extractIngredients()
        
        return RecipeBuilder(name: apiRecipe.title)
            .with(instructions: apiRecipe.instructions ?? "")
            .with(cookingTime: apiRecipe.cookingTime ?? 0)
            .with(servings: apiRecipe.servings ?? 0)
            .addIngredients(ingredients)
            .addTags(apiRecipe.tags ?? [])
            .build()
    }
}
```

**Пример использования:**
```swift
// Получили данные из Generic API
let apiRecipe: APIRecipe = /* данные из API */

// Используем адаптер
let adapter = GenericRecipeAdapter(apiRecipe: apiRecipe)
let recipe = adapter.adapt()

// Или через extension
let recipe = apiRecipe.toRecipe()
```

#### Дополнительно: RecipeAdapterFactory

**Фабрика для создания адаптеров:**
```swift
class RecipeAdapterFactory {
    static func makeAdapter(from mealDBRecipe: TheMealDBRecipe) -> RecipeAdapter {
        return TheMealDBRecipeAdapter(mealDBRecipe: mealDBRecipe)
    }
    
    static func makeAdapter(from apiRecipe: APIRecipe) -> RecipeAdapter {
        return GenericRecipeAdapter(apiRecipe: apiRecipe)
    }
}
```

**Использование:**
```swift
// Единый интерфейс для разных источников
let adapter1 = RecipeAdapterFactory.makeAdapter(from: mealDB)
let recipe1 = adapter1.adapt()

let adapter2 = RecipeAdapterFactory.makeAdapter(from: api)
let recipe2 = adapter2.adapt()
```

**Преимущества адаптера:**
- ✅ Единый интерфейс для разных API
- ✅ Легко добавлять новые источники данных (новый адаптер)
- ✅ Разделение логики преобразования
- ✅ Соответствие Single Responsibility Principle
- ✅ Упрощение кода клиента

**Сравнение:**

❌ **БЕЗ АДАПТЕРА:**
```swift
// Логика преобразования разбросана по коду
// В одном месте:
let recipe1 = Recipe(name: mealDB.strMeal ?? "", ...)

// В другом месте:
let recipe2 = Recipe(name: api.title, ...)

// Дублирование кода, сложность поддержки
```

✅ **С АДАПТЕРОМ:**
```swift
// Единый интерфейс, логика в одном месте
let recipe1 = mealDB.toRecipe()
let recipe2 = api.toRecipe()

// Просто, понятно, легко поддерживать
```
