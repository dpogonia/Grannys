## 🎯 Что было сделано

### 1. Паттерн FACADE (Фасад)
Добавлены подробные комментарии к **существующему паттерну** RecipesRepository:

| Реализация | Файл | Назначение |
|------------|------|------------|
| `RecipesRepository` | Models/Recipe/RecipesRepository.swift | Фасад для Core Data |

**Что делает фасад:**
- Скрывает сложность Core Data (NSManagedObjectContext, NSFetchRequest, NSPredicate)
- Предоставляет простой API для работы с рецептами
- Упрощает код с 15-20 строк до 1 строки
- Централизует логику работы с базой данных

**Методы фасада:**
- `getAllRecipes()` - получить все рецепты
- `saveRecipe(_:)` - сохранить рецепт
- `deleteRecipe(_:)` - удалить рецепт
- `searchRecipes(query:)` - поиск рецептов
- `getFavoriteRecipes()` - получить избранные
- `getAllCategories()` - получить категории
- И другие...

### 2. Паттерн ADAPTER (Адаптер)
**Создано 2 новых адаптера** для унификации данных из разных API:

| Адаптер | Файл | Назначение |
|---------|------|------------|
| `TheMealDBRecipeAdapter` | Models/Recipe/RecipeAdapters.swift | Адаптер для TheMealDB API |
| `GenericRecipeAdapter` | Models/Recipe/RecipeAdapters.swift | Адаптер для Generic Recipe API |

**Что делают адаптеры:**
- Преобразуют TheMealDBRecipe → Recipe (20 полей ингредиентов → массив)
- Преобразуют APIRecipe → Recipe (разные форматы данных)
- Унифицируют работу с разными источниками данных
- Упрощают добавление новых API

**Дополнительно создано:**
- `RecipeAdapter` - протокол для всех адаптеров
- `RecipeAdapterFactory` - фабрика для создания адаптеров
- Extension методы для удобного использования

## 📝 Примеры кода

### FACADE: До и После

❌ **БЕЗ ФАСАДА** (сложно):
```swift
// 15-20 строк кода
let context = CoreDataManager.shared.viewContext
let fetchRequest = NSFetchRequest<RecipeEntity>(entityName: "RecipeEntity")
fetchRequest.predicate = NSPredicate(format: "isArchived == %@", false)
fetchRequest.sortDescriptors = [NSSortDescriptor(key: "createdAt", ascending: false)]
do {
    let entities = try context.fetch(fetchRequest)
    let recipes = entities.compactMap { entity in
        Recipe(from: entity)
    }
} catch {
    print("Error: \(error)")
}
```

✅ **С ФАСАДОМ** (просто):
```swift
// 1 строка кода!
let recipes = RecipesRepository.shared.getAllRecipes()
```

### ADAPTER: До и После

❌ **БЕЗ АДАПТЕРА** (дублирование):
```swift
// В одном месте:
let recipe1 = Recipe(
    name: mealDB.strMeal ?? "",
    recipeInstructions: mealDB.strInstructions,
    // ... много кода для преобразования ...
)

// В другом месте:
let recipe2 = Recipe(
    name: api.title,
    recipeInstructions: api.instructions,
    // ... другая логика преобразования ...
)
```

✅ **С АДАПТЕРОМ** (единый интерфейс):
```swift
// Единый способ для всех API
let recipe1 = mealDB.toRecipe()
let recipe2 = api.toRecipe()

// Или явно:
let adapter1 = TheMealDBRecipeAdapter(mealDBRecipe: mealDB)
let recipe1 = adapter1.adapt()
```

## 🏗️ Архитектурные преимущества

### FACADE в проекте:
1. **Упрощение API** - сложные операции Core Data в 1 строку
2. **Скрытие сложности** - детали Core Data не видны клиенту
3. **Централизация** - вся работа с БД в одном месте
4. **Тестируемость** - легко мокировать фасад
5. **Поддержка** - изменения Core Data не затрагивают клиентов

### ADAPTER в проекте:
1. **Унификация** - разные API → единый формат
2. **Расширяемость** - легко добавлять новые источники данных
3. **Разделение ответственности** - каждый адаптер для своего API
4. **Упрощение кода** - клиент работает только с Recipe
5. **Повторное использование** - адаптеры можно использовать везде
